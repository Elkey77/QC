CS Data Cleaning Logic

  1. export CS SLA: 仅需上传 CS Record 即可即时导出，包含 waybill、channel、Complaint Time、status、Asignee、Total hours。
    • Asignee 规则：读取 F列（Types of secondary questions），若为 "Als zugestellt markiert, aber nicht erhalten" 或 "签收未收到"，则 Asignee 为 "Rania Al Sukhni"；其他值均为 "Ralf"。
  2. export CS driver: 需上传 CS Record 和 Scan records。系统以 waybill 为主键进行关联（Left Join），导出包含 waybill、channel、Complaint Time、Signed date、Last Scan Type、Station、Driver、Total hours。
  3. Total hours 计算规则:
    • 统计起点：Check-in time（M列 / 登记时间）。
    • 统计终点：若工单状态（Z列）为 Ticket Closed，取 Last update（AC列 / 最新更新时间）；若未关闭，取德国当前时间（Europe/Berlin 时区）。
    • 扣除规则：全额扣除每周六、周日及配置的公共假期。
    • 向上取整：计算出的有效工时统一执行向上取整（Math.ceil）输出整数小时。
  4. channel: 移除中文字符，仅保留英文字母。若以 C 或 I 开头取前 2 位，其他取前 4 位。
  5. Station & Driver: 匹配 scan records 中最新扫描记录的站点与司机。
  6. export CS Behavior: 仅需上传 CS Record。分析德语客户诉求（AI列 Problem Description），严格归类为 10 种标准司机行为类别（driver behavior：DNR、Unauthorized Safe Drop、Mishandled Parcel/Damaged、No Doorbell Rung/No Calling、No Card Left、Misdelivered to Neighbor、Unprofessional Conduct、Misdelivered to Wrong Address、Correct address No delivery、Insufficient Delivery Attempts），并将客户诉求归纳为英文摘要（details），按 Station + compliant period + driver behavior 聚合。同一网点同一行为类别下的多个运单合并在单个单元格中（换行排布），compliant period 呈现投诉时间跨度（单日显示 MM/DD，跨天显示 MM/DD-MM/DD）。

latest Scan record Data Cleaning Logic

  1. For each unique waybill (Column A), retains only the record with the latest scan date (Column F).
  2. Formats the scan dates as yyyy/mm/dd.
  3. Maps to exported table format:
    • waybill (Column A)
    • last scan date (Column F, formatted as yyyy/mm/dd)
    • last scan type (Column E)
    • last scan station (Column G)
    • Previous/Next Stop (Column H)
    • Scanner (Column Y, or Dispatcher or receiver if it has a value)
  4. NoUpdate Data Cleaning Logic:
    • For each unique waybill, sorts all its scan records ascending (A-Z) by Scanning Time.
    • Calculates the maximum gap (in days) between adjacent scanning times.
    • If the latest scan type is not "Parcel Signed", also calculates the gap between the latest scan date/time and today's date/time, and includes it in the maximum gap calculation.
    • Determines the classification in a new column NoUpdate:
      • If max gap time < 5 days → "Less 5 days"
      • If 5 days ≤ max gap time < 7 days → "Over 5 days"
      • If max gap time ≥ 7 days → "Over 7 days"
    • Retains the details from the latest scan record for the other columns.
    • Exports as NoUpdate.xlsx with columns: waybill, last scan date, last scan type, last scan station, NoUpdate, Previous/Next Stop, Scanner.

Shipping-Signed Data Cleaning Logic

  1. Filters rows where Delivery outlet contains "BAW".
  2. AscanDate / Month: Parsed from Entry time (AscanDate formatted as MM/DD, Month formatted as YYYY-MM).
  3. Station Mapping:
    • If Latest scanning point contains "BAW" → Latest scanning point.
    • If Latest scanning point contains "ST" → Delivery outlet.
    • Otherwise → Delivery outlet.
  4. Timeline: Latest scan time - Entry time in hours (rounded to 2 decimal places).
  5. Signed: True if Sign for identification is exactly "Normally Delivered".
  6. Aggregated metrics (export 48hAscanSign / export Month):
    • AscanNumber: Total count of Ascans.
    • 24hsignedNumber: Count of packages signed within 24 hours (Timeline ≤ 24).
    • 24hSignedRate: Percentage of packages signed within 24 hours (Timeline ≤ 24).
    • 48hSignedRate: Percentage of packages signed within 48 hours (Timeline < 48).
    • Signed%: Signed / AscanNumber (当前站点的整体签收率).
    • PSigned%: max(signedTimelines) (达到当前签收率的实际耗时，即最后一封已签收件 of the day).
    • P85%/H, P90%/H, P95%/H, P97%/H (记作 P_p, 比如 P_85%):
      • 若 Signed% < p，则不计算该指标，显示为 "-"。
      • 若 Signed% > 99%，按已签收数据计算分位数：getPercentile(signedTimelines, p)。
      • 若 Signed% ≤ 99%，按实际件数计算耗时：耗时排序后第 k = Math.ceil(p * AscanNumber) 个包裹 of the day 的签收耗时，即 signedTimelines[k - 1]。
    • avg time/Hours: Sum(ifnull(Signing time, "") - Entry time) / SignedNumber（按入库 Ascan 批次统计已签收件的平均耗时）。
    • Signed-Ascan avg Timeline (仅 export Month): Sum(Latest scan time - Entry time) / count（按当月实际签收批次统计已签收件的平均耗时，计算逻辑同 Sign-Ascan avg timeline 模块）。
    • Left: 遗留件数：Ascan * (1 - Signed%)，向上取整。
    • Overall (STR): Aggregated metrics across all stations for each date, named "STR".
  7. export today Nodispatch (From 48h Shipping records):
    • Filters rows where Delivery outlet contains "BAW", Sign for identification does not contain "Signed" and is not "Normally Delivered", Transfer and return identification is "未退件" (if present), and Latest problem reason does not contain "lost" (if present).
    • Excludes any "Parcel Signed" (all dates).
    • Excludes "Out of warehouse scan" and "Problem scan" only if latest scan time is today (lastScanDate === todayStr).
    • Maps Station: if latest scan type is "Shipping HUB" or "Outgoing Scan" → Delivery outlet; else → Latest scanning point (with STUTTGART/DE-HQ fallback to Delivery outlet).
    • Exports as TodayNodispatch.xlsx (Sheet: TodayNodispatch) with columns: waybill, AscanDate, station, last scan date, last scan type, postcode.

Sign-Ascan avg timline Data Cleaning Logic

  1. Filters rows where Sign for identification is exactly "Normally Delivered".
  2. Groups records by Station (Latest scanning point) and SignedDate (Latest scan time in MM/DD format).
  3. Timeline: Computes the average time in hours: \[\text{Timeline} = \frac{\sum(\text{Latest scan time} - \text{Entry time})}{\text{count of Waybills}}\] Rounded to 2 decimal places (standard rounding half-up).
  4. Exports as Sign-Ascan avg timline.xlsx.

Pending Data Cleaning & Matching Logic

  1. General Filters: Only keeps records where Latest scan type does not contain "Signed" (case-insensitive), Transfer and return identification is "未退件", Latest problem reason does not contain "lost" (case-insensitive), and Receiving province is "Baden-Württemberg".
  2. Date Format: All exported dates are converted to MM/DD format.
  3. Station Mapping:
    • If Latest scan type = "Shipping HUB" or "Outgoing Scan" → Delivery outlet.
    • Otherwise → Latest scanning point.
  4. Today Nodispatch & Historical:
    • export today Nodispatch: AscanDate (Entry time) range is what is imported; excludes any "Parcel Signed", and excludes "Out of warehouse scan" or "Problem scan" only if latest scan time is today.
    • export get lastest scan: AscanDate is not today.
  5. Driver Matching (for Historical Pending Last):
    • If both scan records and pending records are uploaded, matches by Waybill.
    • Matches for all historical pending records (AscanDate is not today).
    • Updates the fields from the latest scan record as follows:
      • station: if the latest scan record's scan type is "Loading scan", keep pending station; otherwise, update to scan record's last scan station.
      • last scan type: latest scan record's scan type.
      • last scan date: latest scan record's scan date.
      • driver: latest scan record's Scanner (receiver/dispatcher/scanner value) if scan type is "Out of warehouse scan" or "Problem scan"; otherwise left empty.
  6. NoUpdate Pending Export:
    • Filters NoUpdate record rows where Last type of problem (Column T) does not contain "lost".
    • Matches with Scan records for AscanDate, station, last scan date/type, and driver.
    • Delivery count: Matches Waybill with Column A of Delivery times file; if matched, outputs Column H value (Delivery count).
    • OverDays: Takes Column W value (hours) from NoUpdate record, converts to days and rounds down using Math.floor(W / 24).
    • last problem reason: Matches Waybill with Column A of Delivery times file; if matched, outputs Column U value (Last problem reason).
    • whatsApp Sheet: Exports whatsApp sheet (columns: station, msg, TT msg). msg aggregates standard blocks (ask driver to return, warehousing stay ≥ 1 day return to warehouse, outgoing scan find and deliver); TT msg aggregates TT blocks (TT ≥ 4 days return, TT < 4 days & delivery count < 2 redeliver). Empty blocks are hidden and stations with no messages are skipped.
    • Msg Ascan Date Filter: If dates are selected in Msg Ascan Date, message texts in the whatsApp sheet only include waybills matching the selected Ascan Dates. If no date is selected, all dates are included by default. Sheet 1 (NoUpdatePending) always retains all records as a complete ledger.

Driver signed Data Cleaning Logic

  1. Requires uploading the Driver signed file.
  2. Filter valid Signing time: 首先过滤掉所有 Signing time 为空 的数据（剔除未签收或时间缺失的无效行后，再进行后续的随机抽样与异常分析）。
  3. Filters rows from Driver signed where Delivery outlet represents Station.
  4. Column F (index 5) is treated as the courier ID / driver ID.
  5. Client Identification: Identifies client by waybill prefix (JTDE2 / JTDE0 → TT, JTDE1 → TEMU, JTDE9 → SF, JTDE8 → Shein, JTDE3 → speed, others → Others).
  6. 优先抽检与总单量控制 (Special Driver & Total SpotCheck):
    • 若填入了 special driver：系统优先筛选 F 列 Courier ID 匹配该名单的司机，并按配置的配额（TT Signed per driver 与 Others Signed per driver）在对应包裹池中通过 Fisher-Yates 随机抽取。
    • 若设置了 total spotCheck（总抽取单量上限）：若优先抽完 special driver 后累计单量仍未达上限，则自动从其余非特殊司机中随机抽取补充，直至达到 total spotCheck 为止。
    • 若未设置 total spotCheck 且填入了 special driver：仅抽取名单内的特殊司机（白名单模式）。
    • 特殊司机的抽检记录在导出表格中优先置顶排列。
  7. export driver ID signed: 导出抽样运单的 waybillnumber, driverID, station。
  8. export driver signed: 需同时上传 Driver signed 与 Scan records。将抽样运单与最新扫描记录关联，导出 station, signedDate, Client, waybill, driver name。
  9. export abnormal signed: 密集签收异常检测（不受 special driver 影响）。按 courier ID (Column F) 分组并按 Signing time 升序排列，计算相邻签收间隔 signed gap time（分钟），保留 ≤ 阈值的记录。

Receive & Delivery Data Logic

  1. arrive import (DC / HUB Receive):
    • 文件读取后自动删除第 1 行。
    • B 列中包含 BAW 的行识别为有效网点 (Station)。
    • D 列作为各网点的到件量 (receive number)。
  2. export delivery: 结合 delivery import (HUB Delivery) 与 arrive import 导出 delivery.xlsx，包含 3 个 Sheet：
    • dispatch_hub_courier: 各网点、各日期派件员派件明细（dispatched, signed, IN WH, Problems, NoSigned, Signed%）。
    • dispatch_Hub_day%: 网点日维度汇总。matched with received volume from arrive import (B列含 BAW 的各 station 对应 D 列数值之和)，dispatched, courier number, signed, signed%, SPR。
    • dispatch_DC_day%: DC 日维度汇总。B 列包含 BAW 的全属于该 DC，其 received 数量为当日 D 列数值对应总和。
